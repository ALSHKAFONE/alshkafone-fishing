## 3.6.42 — автоматическое сохранение в ВК

GitHub Pages размещает файлы игры. При запуске внутри VK Mini App прогресс
сохраняется через VK Bridge в хранилище пользователя этого приложения.
При обычном открытии сайта вне ВК используется локальное сохранение.

- Перед первым входом игра читает облачную копию и восстанавливает персонажа.
- Первый облачный снимок и последующие игровые изменения сохраняются автоматически.
- Перед подтверждением записи проверяются все части и SHA-256 снимка.
- При обрыве связи предыдущая целая копия сохраняется; подключение повторяется.
- Последняя подтверждённая ревизия позволяет отличать локальные изменения от
  прогресса другого устройства. Если изменились обе копии, игрок выбирает нужную.
- Поддерживаются сохранения совместимой схемы из версий 3.6.10–3.6.42.

`cloud-save.js` содержит протокол и контроллер синхронизации. `index.html`
содержит игровую модель, нормализацию, локальное сохранение и вызов запуска.
Номер версии не входит в ключ локальной карьеры.

## Проверка

```sh
node tests/vk-persistence.vm.cjs
```

Тесты исполняют настоящий контроллер, транзакции VK и функции нормализации
игры. Граница VK Bridge заменена отдельным хранилищем для каждого тестового
игрока. Проверяются восстановление полного прогресса, старые версии,
задержки и ошибки сети, неполная запись, независимые устройства, конфликт,
недоступный localStorage и запуск вне ВК. Это проверка логики сохранения;
отрисовка и реальный мобильный клиент ВК требуют отдельного запуска.

Для проверки в браузере установите Playwright и Chromium, запустите игру
на `http://127.0.0.1:8765/`, затем выполните:

```sh
node tests/vk-persistence.cjs
```
